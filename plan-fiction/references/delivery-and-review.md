# 交付与检查

用于维护构思状态、整理简纲或可动笔的完整大纲、执行交付前内部自检，以及按反馈局部修订大纲。

## 对话过程中维护的工作状态

在构思对话中，助手在内部跟踪以下几项核心状态（无需每轮打印给用户看，仅在方向大变、用户要求回顾或正式交付时汇总）：

- 用户明确偏好的题材气质、篇幅规模与排斥的套路。
- 当前那句核心事件的内容、它吸引读者的疑问点，以及它目前属于“**候选/暂定**”还是“**用户已定**”（局部设定偏好与整篇点子确认严格分开）。
- 用户已敲定的事实、人物关系、关键抉择与结局走向。
- 曾提出但未被用户选中的候选方案（绝不悄悄塞回后续已定大纲）。
- 当前最影响故事成立的一个结构性缺口，以及下一问准备解决什么。

只有在用户明确要求保存文件或指定路径时才将大纲写入磁盘，不私自写入全局配置或记忆文件。

## 简纲交付（试纲或快速确认）

默认先帮用户找到想写的一句话核心事件；若用户明确要求“先拉一版大纲看看”，立即按现有材料交付简纲，用来辅助判断：

1. **核心事件与阅读牵引**：写清已选或标为“暂定”的一句话核心事件，以及它让读者最想追看的具体疑问（不写空泛的题材标签或道德说教）。
2. **人物主线**：主角起点的认定与顾虑 → 它如何影响关键选择 → 结局时人物认知或读者理解的变化。
3. **关键因果节点**：按已有材料列出核心转折，每一步包含“行动 → 结果/认知变化 → 下一步处境”。
4. **结局方向与代价**：写明最终回应；若结局未定，并列 2–3 个不同走向供选择，不擅自替用户拍板。
5. **待定缺口**：明确标出哪些关键环节属于“暂定”。

不为缺少角色姓名或地名而推迟交付，也不擅自编造一串名字让暂定试稿显得像定稿。

## 可动笔的完整大纲

按故事实际复杂度裁剪以下模块（简单短篇无需硬凑空项）：

### 1. 故事定位与核心前提
- 篇幅规模与整体基调（未指定字数时注明当前采用的工作假设）。
- 一句话核心事件，以及贯穿全篇的核心追看问题。
- 若涉及主题探索，写成一句具体处境下的工作命题，不写空洞口号。

### 2. 人物与关系动力
- **主角**：外部具体追求、个人内在意义、旧认定/内在阻碍、一条直接相关的往事，以及结尾如何面对这一矛盾。
- **主要配角**：各自的目的、对主角造成的实际牵制或推动，以及关键知情差（不附无关履历）。

### 3. 故事脉络梗概
- 用一段连贯、朴素的梗概把起因、关键抉择、连带后果与最终结局串起来，让人一眼看清全貌（不写成小说正文或抒情散文）。

### 4. 关键节点表

| 节点 | 具体处境与人物期待 | 反应、选择及动因 | 造成的新局面与后续牵引 |
| --- | --- | --- | --- |
| 开场切入 | 旧平衡已被打破；眼下必须应对什么 | 他为何采用惯常或反常的方式应对 | 立住什么悬念或期待 |
| 中途转折 | 由上一节点的后果自然推演 | 同时体现外在局势与内在判断的变化 | 绝不写“历经重重困难”之类空话 |
| 最终抉择 | 核心两难到了无法回避的时刻 | 他最终做了什么、放弃了什么 | 外部结果、实际代价与理解变化 |

采用非线性叙述的故事，分别列出“**客观事实发生顺序**”与“**正文叙述呈现顺序**”；顺叙故事只列一份即可。

### 5. 关键信息与结构安排
- 仅列出对本篇成立确有作用的设计：叙述视角与知情边界、核心认知差、重要铺垫与结尾呼应、支线或闪回的切入时机与当场用途。简单故事用几句话写明即可。

### 6. 动笔交接说明
- 明确开场第一幕需要立住的局势与期待，留出由用户在正文写作中自由发挥的细节空间，最多提示 1–2 项真正影响下笔的未定事项（不附“开篇正文示范”）。
- 提醒正文叙述与对话的克制原则：当处境、关系与利害已在场景中立住时，直接靠准确的动词（如“说、喊、求”）与人物话语本身传达语气，尽量少用修饰态度的副词（尤其是对话归属语中的情绪副词），不替读者预先总结情绪。

## 交付前的内部自检表

输出大纲前，助手先在内部快速过一遍以下检查项；发现实质断点时再针对最关键的一处询问用户或给出修补建议，绝不把整张自检表直接打印给用户当作业：

| 检查维度 | 失效信号 | 修正动作 |
| --- | --- | --- |
| **点子吸引力** | 只有奇异入口而主体仍是老套路；换掉一个名词就能套进别的题材；扩写后最初的趣味消失 | 退回一句话核心事件重新发散，不靠堆砌场面細節硬救 |
| **故事焦点** | 只有世界观设定、社会议题或一连串偶发事故 | 锚定某个人在此刻的具体追求与两难取舍 |
| **个人意义** | 把主角换成任何路人都毫无区别 | 明确办成或搞砸这件事对此人意味着失去或证明什么 |
| **往事锚定** | 贴了性格或创伤标签，却与当下的具体决定毫无关系 | 把过往经历直接连到眼下的一次犹豫或执拗选择上 |
| **情绪因果** | 遭遇变故后毫无反应，转折处只写一句“他突然想通了”，或靠“愤怒地、绝望地、轻蔑地”等副词硬撑态度 | 删去副词标签，补齐人物原有的期待、受挫后的解读与改变决定的具体台阶 |
| **行动因果** | 场景顺序可随意调换，主角全程被动等待别人安排，或用“巧妙地化解”掩盖具体办法 | 找出前一次选择如何直接造成后一次处境，写出不带副词的具体行动 |
| **压力与节奏** | 困难同质化重复，或从头到尾一味加惨、毫无喘息 | 让每次选择的代价递进，并在冲击后留出消化与重估的空间 |
| **信息边界** | 连基本处境都瞒着读者，或角色动用了未曾获知的未来信息 | 严格分开客观事实、角色已知与读者已知 |
| **铺垫与兑现** | 结尾靠临时冒出的能力/巧合解围，或前文显眼铺垫彻底失踪 | 在前文补上自然铺垫，或删掉无下文的虚假承诺 |
| **支线与闪回** | 离开主线太久，回来后对主线处境毫无影响 | 压缩并入主线、调整插入时机，或明确其当场作用 |
| **篇幅匹配** | 核心转变被一句话带过，旁枝末节却占满篇幅 | 合并重叠角色与重复试探，把空间让给关键抉择 |
| **结局落点** | 戛然而止、只靠突兀反转博眼球，或未回应最初的核心疑问 | 让结局直接回应核心两难及人物为此付出的代价 |
| **决定权归属** | 把助手提议但未获确认的候选直接写成了既定事实 | 恢复“暂定/候选”标注，把选择权交还用户 |

若用户有意尝试某种非常规写法或留白，客观说明那会带来怎样的阅读体验变化，由用户自己拍板。

## 局部修订与读者反馈处理

1. **区分“推翻点子”与“修补结构”**：
   - 若用户对整件事失去兴趣，直接撤回派生大纲，回到一句话点子重新探索。
   - 若用户只改动某一项设定或人物关系，顺着因果链梳理它牵动的动机、知情时机、铺垫与结局，只同步修改受影响的环节，保留用户仍满意的部分。
2. **可操作的诊断格式**：
   - 指出大纲问题时，按“**具体位置 → 读者读到这里会产生什么误解或卡顿 → 缺了哪项关键依据 → 具体修补方向**”说明，不用“略显平淡”“张力不够”等空泛评语，也不用廉价夸奖掩盖结构硬伤。
3. **运用外部读者反馈**：
   - 当用户拿来试读反馈时，帮用户把“**读者实际看懂/卡住的地方**”与“**读者随口开的修改处方**（如加个反派）”区分开：优先解决导致读者误解或失去期待的依据缺口，每次依然只聚焦最关键的一处提问。
